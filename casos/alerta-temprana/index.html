Inicio/Casos/Seguimiento preventivo

A quién vigilar antes de que se atrase

Un ejercicio para ordenar cuentas según la probabilidad de incumplimiento del mes siguiente. El valor está en definir el evento, construir variables con criterio y comparar el modelo frente a reglas que ya podrían utilizarse.

Código en GitHubVer el servicio

Ejercicio con datos públicos. No presenta resultados de clientes ni validación temporal.

Qué se quiso resolver

Evento de interés

Estimar el evento publicado como incumplimiento del mes siguiente en la base de tarjetas de crédito de UCI. No equivale a demostrar una transición exacta de días de mora.

Datos y variables

Se utilizaron datos públicos de Taiwán de 2005, incluyendo comportamiento histórico de pago. Las variables se agrupan para representar atrasos, pagos y utilización.

Cómo explicamos el resultado

Al priorizar el 20 % de las cuentas en este conjunto de prueba, la mejor regla sencilla captura el 35,66 % de los eventos. La combinación de modelos alcanza el 38,78 %: una diferencia de 3,12 puntos porcentuales.

35,66 %

Captura de eventos al priorizar con una regla de atraso histórico y utilización.

38,78 %

Captura de eventos con la combinación de modelos en la partición de prueba.

Son resultados de una partición estratificada de un solo corte transversal. No constituyen evidencia de que el modelo mantenga ese desempeño en otro periodo ni de que un contacto evite el atraso.

Validación y límites

Lo que sí se validó

Partición estratificada de entrenamiento y prueba, validación cruzada en desarrollo y comparación con reglas simples. Se revisaron métricas de discriminación, calibración y priorización.

Lo que falta para un proyecto real

Una muestra temporal longitudinal, control de disponibilidad de datos al decidir, validación en cosechas futuras, monitoreo y prueba del efecto operativo de la estrategia.

Preguntas frecuentes

¿Es un modelo implantado en una empresa?

No. Es un ejercicio académico reproducible con datos públicos.

¿Por qué el repositorio se llama alerta temprana?

Es el nombre histórico del repositorio. Su validación es transversal; no demuestra por sí sola un sistema de alerta temporal.

¿Qué necesitaríamos para aplicar esta idea?

Historial de pagos con fechas, definición clara de mora y suficientes periodos posteriores para una validación fuera de tiempo.
